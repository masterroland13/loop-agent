# 桌面 App 封装与差距（调研）

> L3 research。Loop Agent 现状是本机双进程 Web（Vite/静态 + FastAPI），不是安装包。

## 现状

- 前端 React；后端 FastAPI + SQLite + workspace 沙盒；CLI `loop` 无头。  
- 架构 A0–A4 已完成；产品狗粮接近发版核对。  
- 打开方式：起 uvicorn + 前端，浏览器访问 — **开发者可用，非路人 App**。

## 封装路径（推荐）

| 路线 | 说明 |
|------|------|
| **桌面壳（首选）** | Electron 或 Tauri：开窗启后端、关窗停；加载打包前端或 localhost |
| 安装器 + 浏览器 | 体验弱，端口/依赖冲突多 |
| Docker | 适合服务端；不适合「绑本机文件夹改代码」主路径 |
| 纯 PWA | 无本机后端则无法做 workspace |

封装还须：数据目录（会话库/密钥勿进只读安装树）、首次向导（模型 + workspace）、更新与签名。

## 差距分层

1. **本机狗粮可用** — 已接近（环、门控、压缩、记忆、CoT…）。  
2. **同事可装的桌面 App** — 缺：壳与进程、安装向导、Files 等人机面、日志/升级、平台签名。  
3. **Cursor 级完整表面** — Terminal / Browser / 多 Agent / 云 — 月级，勿与「能用本地 App」同里程碑。

## 建议顺序

1. Files MVP（人用 list/read/write + 面板）  
2. 桌面壳一键启停  
3. 首次配置向导  
4. 签名与自动更新  

CLI 保留为自动化通道，不替代桌面壳。

## 粗工期（一人）

内测安装包量级约 1～2 月（壳 + Files + 向导）；商店级再加签名打磨。
